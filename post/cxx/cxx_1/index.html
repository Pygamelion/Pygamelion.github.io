变量类型

正数原码、反码和补码相同，负数的符号位是1，补码为反码取反后二进制+1 补码之后 → 减法和加法一样操作。有符号和无符号int的编码位数相同，但是对编码的解释不一样…相当于把原来的2147483648之后的内容用来表示从-2147483648开始到-1的负数了

int a = -2147483647;
unsigned int b = 2147483649;

当无符号数和有符号数运算时，有符号的负数 → 一个比较大的无符号正数，所以有一个坑，Vscode的C/C++插件会补全这样的for循环，如果用来比较或计算要留心…

// size_t 在64位系统上相当于 unsigned long 或 unsigned long long
for (size_t i = 0; i < size; i++)
{
  std::cout << std::boolalpha << (i < -1) << '\n'; // 结果为 true
}

几个经典的转换方法 小彭老师视频

  • static_cast 能够确定后果的转换就用这个，不做运行检查，UB在召唤(ゝ∀･)，
  • dynamic_cast ⇒ 依靠typeinfo用于类型层级导航 (虚类（类+虚函数）才有虚表指针/typeinfo指针/RTTI哦，除非转换void*就不需要+虚函数…)
    • 按值将派生类（共有继承）传给基类时，对象切片发生，派生类对象被截断成为基类对象(丢失信息)
    • 按指针/引用将派生类传给基类时，相当于改变地址的解释方式，信息会完全保留(这种情况效果和C强转或者static_cast一致的）。派生类大小 ≥ 基类大小，Cxx默认不允许基类的指针/引用转换为派生类（担心会访问到未指定内存？）但是如果这个 地址完全保留派生类的信息，就可以通过dynamic_cast来转换（转换不是严格匹配的，只要属于cast目标的派生类即可）

dynamic_cast相当于在基类头部放一个指针const std::typeinfo *存着基类的typeid，并随着派生类的构造改变为派生类的typeid，在转换时通过比较typeid就能知道当前内存块的类型，从而决定是否转换（\´ ▽ ` )ﾉtypeid.name()会经过名称重组）

指针转换失败会是空指针，引用转换失败（引用不能是空的 ´ ▽ `）是std::bad_cast异常，最好就不要使用RTTI…

无论是左值引用还是右值引用都必须在声明时初始化，左值引用只能被左值初始化；右值引用只能被右值初始化，它们都是地址，引用相当于指针常量，只能在声明时初始化并且不能更改

只有同时满足下列条件，右值引用效率更高：

  1. 右值是一个对象，对象含有指向堆空间数据的指针成员
  2. 右值作为函数参数传递
  3. 函数内部对右值对象数据进行了拷贝操作
class Object
{
public:
    Object(){m_data = new Data()}
    Object(const Object& obj) {m_data = new Data(obj.m_data);};
    Object(Object&& obj) = default;
    ~Object(){delete m_data;m_data=nullptr;}
private:
    Data *m_data; //满足条件1
};

std::vector<Object> vec;
vec.push_back(Object()); //满足条件2和3

经典原始指针

虽然有了智能指针，但是稍微了解原始指针对于增长见识有帮助 (例如智能指针例如unique_ptr还是引入了overhead的，毕竟它利用了堆栈，不像原始指针可以寄存器上传递…

原始指针变量相当于“存入其它变量地址的值”的变量，它和地址稍有不同: 指针类型保留了对地址(内存)的解释方式（比如数组指针的自增增加的地址值不同），void*存储但没有解释地址，C中常用C-style Conversion来转换成其它类型以做到多态 (✿◠‿◠)?

int* a1 = new int(3);
int** a1_ptr = &a1; // 不能用一级指针去存指针的地址
std::cout << a1 << '\n'; // 0000015740779620
std::cout << *((int*)a1) << '\n'; // a1 相当于字符 0x0000015740779620
std::cout << **a1_ptr << '\n'; // 二级指针
std::cout << *((int*)(*a1_ptr)) << '\n'; //取一次地址相当于变成一级指针地址

struct Counter {
    int value = 0;

    // 前置 ++x;
    Counter& operator++() {
        ++value;
        return *this;
    }

    // 后置 x++; 后置必须返回旧值，不能是引用
    // 能用前置 ++ 就别用后置 ++
    Counter operator++(int) {
        Counter tmp = *this;
        ++value;
        return tmp;
    }
};

Ranges

Ranges 是 STL 自 1994 诞生以来最大的一次架构升级

STL（由Alexander Stepanov 设计）核心模型是 算法 + 迭代器对 std::sort(v.begin(), v.end()), 一个区间相当于两个iterator ⇒ 容器与算法解耦合, 方便泛型编程

解决一些历史遗留问题：

  • [first, last) 这个区间两个迭代器是没有语义关联的 
    std::vector<int> a{1,2,3};
std::vector<int> b{4,5,6};

std::sort(a.begin(), b.end()); // 编译通过，逻辑灾难
  • 区间没有统一对象，无法将区间作为一个整体传递
  • 迭代器生命周期问题 
    auto it = vec.begin();
vec.push_back(10);   // 迭代器失效
  • 迭代器必须同类型是很大的限制 
    char* begin    '\0' sentinel 结束
ranges 修复：Sentinel 模型, 允许iterator != sentinel
sentinel_for<S, I> 表示 I 可与 S 比较
方便表示 无限序列/流输入/null 终止字符串/网络流/生成器
  • STL 算法全部是 Eager Evaluation，每一步都产生新容器，多次遍历，内存浪费，性能低 ranges 引入 Lazy Evaluation views 不存储数据，只是“计算描述” 
    auto v = filter(vec);
auto v2 = transform(v);
// 改进到
auto r =  vec
  | std::views::filter(...)
  | std::views::transform(...)
  | std::views::take(10);

template <std::ranges::random_access_range R, class Comp = std::ranges::less>
    requires std::sortable<std::ranges::iterator_t<R>, Comp>
void ShellSort(R& r, Comp comp = {})
{
    auto first = std::ranges::begin(r);
    auto last = std::ranges::end(r);
    auto step = (last - first) / 2;
    while (step > 0)
    {
        for (auto i = first + step; i < last; ++i)
        {
            auto key = std::ranges::iter_move(i);
            auto j = i;

            while (j >= first + step && comp(key, *(j - step)))
            {
                *j = *(j - step);
                j -= step;
            }

            *j = std::move(key);
        }
        step /= 2;
    }
}
